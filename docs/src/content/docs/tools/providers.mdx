Some tools can get the same thing from more than one service. GIFs can come from KLIPY, GIPHY, Wikimedia Commons, GifCities or packs on your phone. Each of these tools keeps a **Providers** list at the top of its settings page, and every list works the same way, much like the locations of [backups](/privacy/backup/).

## The list

Each row is one provider: its place in the order, its logo, its name, what it is using (your key, the key in this build, a server address, or files on the phone), and a switch. A long name or address wraps onto a second line rather than being cut off.

- **Drag the number** at the start of a row (the grip under it) to change the order. The tool asks the providers in this order. With TalkBack, the row's actions include **Move up** and **Move down**.
- **Switch a row off** to skip it without losing its setup.
- **Tap a row** to open the provider's setup: its key, its server address, a model, an engine, or a nickname. A provider with nothing to set up shows what it is.
- **Remove**, at the bottom of that sheet, takes the provider out of this tool's list. If no other tool uses its key or server, the key and address are deleted too, and the dialog says so first.
- **Add a provider** opens a sheet of every kind this build can use, in the same order on every build. A kind that needs nothing typed in is added at once. The rest open the setup first.
- **Reset to default** appears once you have changed the list, and puts it back to the list this build starts with.

A row with a problem says what it needs in red: an API key, a server address, a model name, or an imported GIF pack. Such a row is skipped until it is fixed.

Rows show the service's own logo where the app carries one. The logos are small vector drawings from [Simple Icons](https://simpleicons.org/) or from each project's own repository, and are in the app itself, so drawing them never reaches the network. A one-colour logo is lightened on a dark theme when the brand's colour is close to black, and a logo whose colours would vanish on one theme (KLIPY, Lingva, Tavily) sits on a small plate of its own.

## Shared keys and servers

A provider is set up once, and every tool that lists it uses the same setup. A KLIPY key added on the GIF page also works for stickers. The setup sheet says which other tools use it, under **Also used by**. Edit it on either page and both change.

Server kinds can be added more than once, each with its own address and nickname: two Wikimedia wikis, say. When you add one on another tool's page, the add sheet offers the servers you already set up, under **Use**, so you don't type the address twice.

## Two of the same provider

A service you set up with a key can also be added a second time, with another key or another account: two KLIPY keys, two DeepL accounts, a Brave key of your own beside the one in the build. Tap the kind again in **Add a provider**. The second one always needs its own key, since the key in the build already belongs to the first. Give each a **Nickname** so the list and the keyboard can tell them apart; a row without one shows the last four characters of its key.

This works on the GIF, sticker, translate, web and image search, online text scanning, photo translation and AI lists. Background photos, currency rates and the word sources ask a service by its name, so they keep one of each.

When a list asks **One at a time**, the second one is simply the next provider down. On the GIF and sticker lists in **Tabs** or **Mixed**, and on any list set to **Choose in the panel**, a setting called **Two of the same provider** appears as soon as one kind is on the list twice:

- **As backups** (the default for a second key): they act as one provider, with one chip and one entry in the panel. The first is asked, and the next only when it fails, for example when a key runs out of quota.
- **Separately**: each one is its own provider, with its own chip, its own entry in the panel, and its own share of a mixed grid. Two servers of one kind, like two Wikimedia wikis, start out this way.

## How a tool uses its list

Most tools ask **One at a time**: the first provider that is on, and the next one only if the first fails or has nothing. The GIF and sticker panels can also show their providers as **Tabs** (a chip for each) or **Mixed** (all of them at once, in one grid). The smart home list is always mixed: every home on it is connected, and the order is the order their rooms appear in. Packs on your phone always get a chip of their own, and GIPHY keeps its own chip in Mixed mode, because its terms do not allow mixing its results with another service's.

The AI list is always **Choose in the panel**: one service answers at a time, the one picked under **In use** on the AI page or with the AI panel's model picker, and that pick is kept. The voice typing list is always one at a time: dictation uses the first engine that is on and can run, and a language can be given another engine of its own.

Translate, the dictionary, web and image search, online text scanning and photo translation can instead **Choose in the panel**. The panel then shows a chip with the provider in use, and tapping it lists the providers that are on. Only the one you pick is asked, with no fallback to the next. Picking another one runs the same request again with it. The choice lasts until the keyboard restarts, and then the first provider in the list is the one in use again. With only one provider on, there is nothing to choose and the chip stays hidden. The AI's own tools always use the list in order, whatever the mode.

A provider that can't be reached (no answer, a server error, too many requests) is skipped for a minute, so the next one answers at once instead of after a timeout. If every provider is in that state, they are all asked anyway. Editing a provider clears this, so a fixed key is tried straight away.

## What each build offers

Every build offers every kind it can run, your own servers included, in the same order and with none put first. The tags under each kind (free software, on the phone, your own server, needs your key) say what it is. What changes between builds is the list a fresh install starts with.

| Build | Starts with |
|---|---|
| Google Play and GitHub | The services this build has keys for |
| F-Droid | Services that need no proprietary key |
| No internet | Only what runs on the phone; nothing else can be added |

Updating the app does not change your lists. Until you edit a list, it is worked out from your earlier settings, so the same providers are asked in the same order with the same keys. When an update adds a word source that needs no setup (a new dictionary, say), it joins the end of the dictionary, synonym or vocabulary list, switched on. One you removed stays removed.
