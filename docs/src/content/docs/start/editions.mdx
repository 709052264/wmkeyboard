WM Keyboard is one app built from one source tree. Up to 0.6.2 it came in two editions, Full and Lite. From 0.6.3 there is no Lite: every build has the same features, and what differs is where the larger parts come from.

- **Standard**, from GitHub and Google Play. Feature libraries such as the handwriting recogniser or the offline voice engines are not in the APK. Each one downloads the first time its feature is used, from Play on a Play install and from the project's own data repository otherwise.
- **Offline**, from GitHub. The same app with no internet permission at all. Every feature library and every interface language is built in, because it could never fetch them.
- **F-Droid.** The standard build without Google's SDKs (ML Kit, LiteRT and LiteRT-LM), which F-Droid does not accept. Its feature libraries download only after you agree to it under Privacy, since that skips F-Droid's own checks.

## What the F-Droid build leaves out

The F-Droid build is compiled with one switch on, `wmkb.enableFdroid`, which leaves Google's SDKs out and puts small stand-ins where the code called them. That hides four tools from the toolbox:

| Tool | What it does | <Flavor edition="fdroid" /> |
|---|---|---|
| Handwriting | Write words by hand (finger or S Pen) with on-device recognition | Not available |
| Text scan (OCR) | Point the camera at printed text and type it | Not available |
| QR & barcode scanner | Scan a QR code or barcode and insert its text | Not available |
| Document scanner | Scan a document with Google's scanner and send it as an image | Not available |

There's no toggle to flip. The setting never renders at all. The same check hides these tools everywhere they could otherwise show up: the toolbox panel, the Tools settings screen, [settings search](/reference/settings/), the hardware-keyboard tool shortcuts, and the onboarding tool picker. Grammar check is in every build, and so is the Harper spell checker under Android's system spell-checker settings, because F-Droid compiles Harper from source.

The document scanner has a second condition on top of that. It's an activity inside Google Play services rather than this app's own code, so the same check drops it on a standard build running on a phone without Play services. Text scan and QR scanning stay on such a phone, because their models come with the app.

Handwriting carries one nuance of its own. Its "Handwrite" option under **What a swipe does** (draw letters instead of gliding) needs the same recognition model, so the F-Droid build doesn't offer it. The choice itself appears once you've turned on gesture typing, and the F-Droid build still offers its other two options.

## Other parts the F-Droid build lacks

A few more features sit inside tools that every build has:

- **Offline voice engines.** Every build offers [offline Whisper](/tools/whisper/) with its whisper.cpp models, [offline Asr4All](/tools/asr4all/), English dictation that writes the words while you speak, [offline Parakeet](/tools/parakeet/) for 25 European languages and [offline Moonshine](/tools/moonshine/), a small quick English model. The F-Droid build lacks Whisper's older LiteRT models and [offline Whistle](/tools/whistle/), whose library F-Droid can't build from source. The system recognizer stays the default everywhere until you switch it.
- **LiteRT-LM models for on-device AI.** The F-Droid build has the [AI writing tools](/tools/ai/) "On your device" provider, but it runs only the [GGUF models](/tools/ai/#gguf-models-on-llamacpp) on llama.cpp, which F-Droid builds from source. The LiteRT-LM list (Gemma 4, Gemma 3, Qwen and SmolLM2 as `.litertlm` or `.task` files) is left out, and importing one of those files says it needs the Google Play or GitHub build.
- **Smaller pieces.** The sticker editor's one-tap background remover, ML Kit's on-device translator (Bergamot, the open-source one, is in every build), Google Home in the smart home tool, the NPU as a compute choice, and search by meaning.

## Why the download is small

None of the builds that can reach the internet carry their feature libraries in the APK. On Play each arrives as an on-demand part the first time its feature is used: the LiteRT-LM runtime, ML Kit's translator, the LiteRT interpreter behind offline Whisper, the sticker editor's own background remover and the scanner's PaddleOCR reader, ML Kit's handwriting recogniser, the whisper.cpp, ExecuTorch and Whistle libraries behind the other offline voice engines, the Tesseract library behind the scanner's offline reader, and the Harper library behind the grammar tool and the spell checker. GitHub's standard build fetches the same libraries itself, checked against a hash the APK carries, and so does the F-Droid build once you allow it.

Most of what that saves is runtime *library code*, not language data. The biggest models these features use (handwriting recognition per language, Whisper's transcription graphs, LLM weights) download on demand into app storage in every build, so none of those sit in the APK either.

The offline build is the exception, and much larger: it can never download anything, so all of it is inside. Figures shift as dependencies update; see [Installation](/start/installation/#choosing-a-build).

## Privacy doesn't change between builds

The F-Droid build is a build with fewer Google parts, not a more private one. Every feature it lacks already runs on-device and says so in its own settings caption. Handwriting recognition "runs fully on your device with Google ML Kit." Text scan says "no photo and no text leaves your device, and it works offline." Document scanning says "the processing runs on your device." Whisper "runs fully on your device across many languages and sends no audio anywhere." The on-device AI caption says the text you run an action on "stays on your device." The privacy policy the About screen opens does differ, because ML Kit reports usage to Google and the F-Droid build has no ML Kit to do so.

The Version row shows "Standard build (release) · code …", or "Offline build" for the offline one, with " · F-Droid" or " · Play Store" after the build type when the app came from a store. There's a quicker visual check for F-Droid's, though. Open the toolbox. If Handwriting, Text scan, QR & barcode scanner and Document scanner are all there, you're not on the F-Droid build.

## Switching builds

There's no in-app switch. Which build you have depends on which APK you installed. They share a package name and the release signing key (F-Droid publishes its build with the project's own signature, from 0.5.10 on), so installing another build over your current one is a normal app update. Your settings, themes, learned words and the rest of the app's data stay in place. A GitHub install from 0.6.2 or earlier that was Lite moves onto the standard build at its next update.

## Details & edge cases

- In the F-Droid build, Handwriting, OCR, QR and Doc scan are never "enabled but hidden" in some special sense. All four are still listed among the keyboard's default enabled tools internally. They just never pass the supported-tool check that decides what renders, and that is true in any build.
- Build release APKs on different machines without sharing a signing keystore and the packages carry different signatures. Installing one over the other then fails the way any mismatched-signature update does (see [Installation → Details & edge cases](/start/installation/#details--edge-cases)).
- Exported debug logs stamp which language build (`intl` or `en`) produced them, which the bug-report bot needs to read the crash trace.
